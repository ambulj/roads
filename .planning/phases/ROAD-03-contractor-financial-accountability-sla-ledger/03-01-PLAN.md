# Plan 03-01: IRC:SP:20 Clause 14 Automated Contractor Penalty Calculation & Escrow Ledger Backend

<planning_context>
### Objective
Establish the automated financial accountability backend for municipal road maintenance contractors under Indian Roads Congress standards (**IRC:SP:20 Clause 14** and **MoRTH Section 3000**). Build an autonomous debit calculation engine that identifies recurrent pavement distress within a 15-meter corridor and 36-month (1,095 days) Defect Liability Period (DLP), computes statutory penalty escalations (₹25,000 for 1st recurrence, ₹50,000 for 2nd, ₹1,00,000 + GeM debarment for 3rd), deducts penalties from contractor security deposit escrows down to non-negative balances, generates Comptroller and Auditor General (CAG) compliant Public Financial Management System (PFMS) transaction vouchers with SHA-256 evidence hashes, and serves full ledger accounting via dedicated REST APIs.

### Scope Boundaries
- **In Scope:**
  - Database schema expansion in `backend/app/models/db_models.py`:
    - `DBContractor` model tracking legal CIN, assigned corridor, zone, ₹50L standard security deposit, cumulative penalties deducted, SLA on-time rates, quality index, and debarment risk.
    - Extended fields on `DBDistressCluster`: `contractor_id`, `warranty_end_date`, `escrow_deposit_inr`, `concurrence_passes_count`, `verification_status`.
    - Enhanced fields on `DBContractorPenalty`: `contractor_id`, `pfms_txn_ref`, `evidence_sha256`, `patrol_bus_id`, `measured_gz`, `threshold_gz`.
  - Service layer in `backend/app/services/contractor_service.py`:
    - Tiered Clause 14 penalty formula: `calculate_clause14_penalty(recurrence_count: int) -> tuple[float, bool]`.
    - 36-month (1,095 days) Defect Liability Period temporal boundary evaluation.
    - 15-meter corridor spatial matching with dual PostGIS (`ST_DWithin`) and SQLite (Haversine bounding box fallback) support.
    - Security escrow debit deduction with non-negative balance clamping ($\text{Balance} = \max(0, \text{Deposit} - \text{Debit})$) and critical debarment threshold alerts.
    - CAG-compliant PFMS voucher reference generation (`PFMS/DLP-ESCROW/{YYYY}/{MMDD}-{HEX6}`) and SHA-256 evidence hashing.
    - Debarment registration in `DBContractorDebarment`.
  - REST API endpoint implementation in `backend/app/api/endpoints/contractors.py`:
    - `GET /api/contractors/ledger`: Summarized contractor performance, escrow balances, and SLA scores.
    - `GET /api/contractors/penalties`: Historical penalty dockets with PFMS voucher references and telemetry proofs.
    - `GET /api/contractors/{contractor_id}/escrow`: Granular escrow ledger, holdbacks, and settlements.
    - `POST /api/contractors/penalties/auto-debit`: Automated debit execution against fresh defect telemetry.
    - `GET /api/contractors/debarments`: Debarment register with GeM portal notices.
  - API router mounting in `backend/app/api/router.py`.
  - Exhaustive automated unit and endpoint test suite in `backend/tests/test_contractor_ledger.py`.
- **Out of Scope:**
  - Multi-pass concurrence cross-bus verification gating logic and `POST /api/work-orders/{id}/verify-concurrence` (Plan 03-02).
  - Frontend React ledger tables and work order console bindings (Plan 03-02).
  - National Electronic Toll / NACH real-time banking clearing integrations (requires municipal engineer digital signatures).

### Threat Model
- **T-03-01: Fraudulent Contractor Self-Clearing**: Contractors self-certify patch repairs without physical verification. Mitigated by binding all status progressions to automated telematics logs and immutable `DBRepairAudit` entries.
- **T-03-02: Escrow Over-Deduction / Negative Balances**: Consecutive penalty debits exceed remaining security deposit, causing corrupt accounting states. Mitigated by clamping remaining deposit balance to $\ge 0$ and automatically raising a critical GeM debarment warning when balance drops below 20% of initial deposit.
- **T-03-03: Spoofed Telematics Passes / Evidence Tampering**: Malicious agents submit fabricated telematics or modify penalty records. Mitigated by generating immutable SHA-256 evidence hashes linking contractor CIN, cluster code, penalty amount, and detection timestamp.
</planning_context>

2. Implement `backend/app/services/contractor_service.py`:
   - `def calculate_clause14_penalty(recurrence_count: int) -> tuple[float, bool]`:
     - If `recurrence_count == 1`: returns `(25000.0, False)`
     - If `recurrence_count == 2`: returns `(50000.0, False)`
     - If `recurrence_count >= 3`: returns `(100000.0, True)` (True indicates debarment notice trigger)
   - `def check_within_36_month_dlp(resolved_date_iso: str, detected_date_iso: str) -> bool`:
     - Evaluates $\Delta t = t_{\text{detected}} - t_{\text{resolved}}$. Returns `True` if $\Delta t \le 1095\text{ days}$ (36 months), `False` otherwise.
   - `def generate_pfms_voucher_ref(dt: Optional[datetime.datetime] = None) -> str`:
     - Formats deterministic CAG-compliant reference: `PFMS/DLP-ESCROW/{YYYY}/{MMDD}-{HEX6}`.
   - `def compute_evidence_hash(cin: str, cluster_code: str, amount: float, timestamp: str) -> str`:
     - Calculates `hashlib.sha256(f"{cin}:{cluster_code}:{amount}:{timestamp}".encode()).hexdigest()`.
   - `def find_recurrent_distress_cluster(lat: float, lng: float, detection_time_iso: str, db: Session, buffer_meters: float = 15.0) -> Optional[DBDistressCluster]`:
     - PostGIS query if PostgreSQL dialect: `ST_DWithin(geom::geography, ST_SetSRID(ST_Point(lng, lat), 4326)::geography, buffer_meters)`.
     - SQLite fallback query: Bounding box candidate filter followed by `haversine_distance_m(lat, lng, c.lat, c.lng) <= buffer_meters`.
     - Filters for clusters with `status.in_(["resolved", "verified_closed"])` and verified within 1,095 days.
   - `def execute_contractor_auto_debit(db: Session, cluster: DBDistressCluster, measured_gz: float, bus_id: str, notes: Optional[str] = None) -> DBContractorPenalty`:
     - Resolves contractor by `cluster.contractor_id` or `cluster.assigned_agency`.
     - Increments recurrence count for contractor along the corridor.
     - Computes penalty amount & debarment trigger via `calculate_clause14_penalty(recurrence_count)`.
     - Deducts penalty from `contractor.penalties_deducted_inr`. Calculates remaining balance $\ge 0$.
     - If balance $< 0.20 \times \text{security_deposit}$ or recurrence $\ge 3$, sets `contractor.debarment_risk = "Critical Debarment Warning"`.
     - Creates `DBContractorPenalty` with PFMS voucher reference, SHA-256 evidence hash, `measured_gz`, `bus_id`.
     - If debarment triggered, creates `DBContractorDebarment` record.
     - Updates `cluster.status = "REPAIR_FAILED_RECURRENCE"` and `cluster.verification_status = "REPAIR_FAILED_RECURRENCE"`.
     - Logs `DBRepairAudit` verdict `REPAIR_FAILED_RECURRENCE`.
     - Commits session and returns penalty object.
