# Plan 12-01: Telematics Velocity-Normalized Shock, Optical-to-Axle Lag Synchronization, and Heading-Aware Road Snapping

<planning_context>
### Objective
Ground RoadSaathi's telemetry ingestion, sensor fusion, multi-pass concurrence validation, and spatial map-matching in authentic vehicle dynamics and urban GPS multipath physics in accordance with Milestone `v4.0` and Requirements `PHYSICS-01` and `PHYSICS-02`:
1. **Speed-Normalized Vertical Shock Telematics ($G_{norm}$)**:
   - Implement velocity-normalized acceleration metric:
     $$G_{norm} = \begin{cases} 0.0 & \text{if } v_{kmh} < 5.0 \\ \frac{|G_z - 1.0|}{\max(0.2, v_{kmh} / 30.0)} & \text{if } v_{kmh} \ge 5.0 \end{cases}$$
   - Baseline reference speed $v_{ref} = 30.0\text{ km/h}$ preserves exact equivalence ($G_{norm} = |G_z - 1.0|$) with legacy calibrations.
   - Enforce idle floor suppression ($v < 5.0\text{ km/h}$) to eliminate false alarms from passenger boarding bounces, door slams, and bus stop idling.
   - Boost crawl traffic sensitivity (detecting $0.15g$ potholes at $10\text{ km/h}$ as severe $0.45g$ defects) and suppress highway vibration (normalizing $0.50g$ bridge expansion joints at $60\text{ km/h}$ down to $0.25g$).
2. **Wheelbase Optical-to-Axle Physical Lag Offset ($\Delta t$) & Dual-Confidence Distress Mode**:
   - Compensate for the physical distance between windshield dashcam and bus axles ($d_{cam\_to\_axle} = 5.2\text{ m}$):
     $$\Delta t = \frac{d_{cam\_to\_axle}}{v_{mps}} = \frac{5.2\text{ m}}{v_{kmh} / 3.6}$$
   - Synchronize optical events $t_{cam}$ and IMU shocks $t_{imu}$ within asymmetric time window $[t_{cam} + \Delta t - 150\text{ms}, t_{cam} + \Delta t + 250\text{ms}]$.
   - Implement dual-confidence classification:
     - **Confirmed Impact (P0 / P1)**: Optical cavity detection confirmed by synchronized $G_{norm} \ge 0.25$ shock.
     - **Visual Distress (P2 Routine)**: Optical cavity confirmed ($\ge 0.85$) without mechanical axle strike ($G_{norm} < 0.20$), preserving genuine road defects when drivers actively swerve or straddle the crater.
     - **Shock-Only Telematics**: $G_{norm} \ge 0.35$ without optical verification (sub-surface void or dark/wet night).
3. **Heading-Aware Dual Carriageway Road Snapping**:
   - Enforce $\pm 30.0^\circ$ circular angular difference filter between vehicle heading $\theta_{bus}$ and candidate road centerline azimuth $\theta_{road}$:
     $$|\Delta \theta| = \min(|\theta_{bus} - \theta_{road}|, 360^\circ - |\theta_{bus} - \theta_{road}|) \le 30.0^\circ$$
   - Disqualify opposite-lane candidate segments ($|\Delta \theta| > 30.0^\circ$), preventing GPS multipath reflections ($5 - 12\text{ m}$) under metro viaducts from snapping to opposing carriageways.
   - Implement low-speed bearing persistence: when $v_{kmh} < 3.0\text{ km/h}$ and heading is unstable or undefined, persist the last known valid bearing ($v \ge 5\text{ km/h}$) for up to 60 seconds.
   - Cross-database parity: PostgreSQL PostGIS `ST_Azimuth` filter and SQLite Python geodesic azimuth calculation.

### Scope Boundaries
- **In Scope**:
  - `backend/app/services/sensor_fusion_engine.py`: $G_{norm}$ calculation, axle lag offset $\Delta t$, asymmetric time window matching, dual-confidence classification.
  - `backend/app/services/concurrence_service.py`: speed-aware concurrence gating with $30.0\text{ km/h}$ default for 100% backward compatibility.
  - `backend/app/services/clustering_service.py`: heading-aware road corridor snapping, low-speed bearing persistence cache, circular delta filter.
  - `backend/app/services/map_matching_engine.py`: opposite-carriageway candidate pruning.
  - `backend/app/services/telemetry_buffer.py`: priority queue threshold updated to $G_{norm} \ge 0.30$.
  - `backend/app/api/endpoints/telemetry.py`: expose $G_{norm}$ and distress classifications in responses and WebSocket broadcasts.
  - `backend/tests/test_telematics_physics.py`: comprehensive unit test suite covering all physics, lag, and spatial heading formulas.
  - Existing regression test suites: `test_concurrence_gating.py` and `test_spatial.py`.
- **Out of Scope**:
  - No database migration or schema breakage; SQLite / PostgreSQL tables remain compatible.
  - No new external C++ or Python libraries.
  - No modifications to frontend React components (frontend verified building cleanly).

### Threat Model
- **T-12-01: Regression on Existing Concurrence Tests from Missing Speed Parameter**:
  - *Risk*: Legacy tests in `test_concurrence_gating.py` provide test dictionaries with `vertical_gz` but lack `speed_kmh`. If speed defaults to $0.0$, the idle floor suppresses $G_{norm}$ to $0.0$, causing broken test assertions.
  - *Mitigation*: In `concurrence_service.py`, default `speed_kmh` strictly to `30.0`. Since $30 / 30 = 1.0$, $G_{norm} = |G_z - 1.0|$ identically, preserving 100% backward compatibility for all existing tests and assertions.
- **T-12-02: Circular Heading Boundary Wraparound (360°/0° Divergence)**:
  - *Risk*: Linear subtraction $|5^\circ - 355^\circ| = 350^\circ > 30^\circ$ incorrectly disqualifies candidate road segments pointing North.
  - *Mitigation*: Circular minimum delta formula:
    `diff = abs(h1 - h2) % 360.0; min(diff, 360.0 - diff) <= 30.0`.
- **T-12-03: PostGIS Performance Degradation on Spatial Azimuth Calculation**:
  - *Risk*: Computing `ST_Azimuth` on all segments in large road networks would degrade spatial indexing performance.
  - *Mitigation*: The `ST_DWithin` spatial index filter runs first (leveraging GiST R-Tree index), pruning candidates to $\le 5$ within the 15m buffer before evaluating azimuth. Spatial query latency remains $< 5\text{ ms}$.

       ```python
       def circular_heading_delta(h1: float, h2: float) -> float:
           """Computes minimum circular angular difference [0, 180] between two compass headings."""
           diff = abs(h1 - h2) % 360.0
           return 360.0 - diff if diff > 180.0 else diff

       def calculate_geodesic_azimuth(lat1: float, lon1: float, lat2: float, lon2: float) -> float:
           """Computes initial forward geodesic azimuth in degrees [0, 360) from Point 1 to Point 2."""
           phi1, phi2 = math.radians(lat1), math.radians(lat2)
           dlam = math.radians(lon2 - lon1)
           y = math.sin(dlam) * math.cos(phi2)
           x = math.cos(phi1) * math.sin(phi2) - math.sin(phi1) * math.cos(phi2) * math.cos(dlam)
           bearing = math.degrees(math.atan2(y, x))
           return (bearing + 360.0) % 360.0
       ```

## Must Haves

### Truths
- $G_{norm} = 0.0$ when $v_{kmh} < 5.0\text{ km/h}$ (idle floor suppression protects against passenger boarding and bus stop idle bounces).
- $G_{norm} = \frac{|G_z - 1.0|}{\max(0.2, v_{kmh} / 30.0)}$ standardizes vertical shock across all transit speeds.
- Windshield dashcam to bus rear axle physical distance is $5.2\text{ m}$, yielding physical lag $\Delta t = \frac{5.2}{v / 3.6}$ (e.g. $520\text{ ms}$ at $36\text{ km/h}$).
- The optical-to-IMU matching window is $[t_{cam} + \Delta t - 150\text{ms}, t_{cam} + \Delta t + 250\text{ms}]$.
- Driver swerves and wheel straddles are preserved as `VISUAL_DISTRESS_UNSTRADDLED` (P2 Routine) and never dropped.
- Road corridor snapping rejects candidate segments with circular angular difference exceeding $30.0^\circ$.
- Low-speed vehicles ($< 3\text{ km/h}$) persist their last known valid bearing ($v \ge 5\text{ km/h}$) for up to 60 seconds.
- Concurrence service defaults `speed_kmh` to `30.0`, preserving 100% backward compatibility for all existing tests.
