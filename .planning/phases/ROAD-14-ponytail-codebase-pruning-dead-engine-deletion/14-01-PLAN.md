# Plan 14-01: Ponytail Codebase Pruning & Dead Engine Deletion

<planning_context>
### Objective
Execute an aggressive, surgical pruning of speculative, theoretical, and unmounted mock engines under the Ponytail principle (*"The best code is the code never written"*), fulfilling Milestone `v4.0` and Requirement `SIMPLIFY-01`:
1. **Backend Mock Engine Deletion (D-14-01)**:
   - Permanently delete `backend/app/services/federated_edge_engine.py` (352 LOC of mock PyTorch/FedAvg edge simulation; transit buses run static INT8 ONNX models on RK3588 NPUs, never on-device gradient backpropagation).
   - Permanently delete `backend/app/services/markov_deterioration.py` (205 LOC of theoretical Markov chain matrix exponentiation; municipal pavement engineering relies on empirical sensor readings, vertical shock $G_z$, profilometer IRI, and multi-pass concurrence).
2. **Dead Endpoint Pruning (D-14-02)**:
   - In `backend/app/api/endpoints/city_brain.py`: Hard-delete speculative routes (`/federated-round`, `/bandwidth-schedule`, `/model-rollout`, `/model-rollback`, `/edge-diagnostics`) and their associated Pydantic request models (`FederatedRoundRequest`, `BandwidthScheduleRequest`, `ModelRolloutRequest`, `RollbackRequest`), while rigorously preserving all 10 real operational endpoints (0/1 Knapsack budget optimizer, shift triage, Section 198A XAI reasoning traces, closed-loop KPI evaluation, chronic failure clustering, lifecycle state machine, observation decay, map matching, 3D bounding box lifting, and domain adaptation).
   - In `backend/app/api/endpoints/analytics.py`: Hard-delete speculative Markov decay routes (`/deterioration-matrix`, `/simulate-deterioration`), while preserving all 7 operational analytics routes (`/corridors`, `/trends`, `/agency-performance`, `/defect-distribution`, `/lifecycle-distribution`, `/pois`, `/public-transparency`).
3. **Frontend Dead Component & Type Pruning (D-14-03)**:
   - Permanently delete `frontend/src/components/analytics/CityBrainHub.tsx` (941 LOC dead component that was never imported or mounted in any router, workspace, or navigation tab).
   - In `frontend/src/services/api.ts`: Remove `triggerFederatedRound` and `getFleetEdgeDiagnostics` client methods, removing dead type imports.
   - In `frontend/src/types/index.ts`: Remove dead interfaces `FederatedRoundResult`, `FleetEdgeDiagnosticsResult`, `EdgeNPUDiagnostic`, and `SSDRingBufferMetrics`.
4. **Test Suite Alignment & Invariant Guarantee (D-14-04)**:
   - Update `backend/tests/test_api_endpoints.py` (`test_26`) to assert HTTP 404 (Not Found) on pruned endpoints, proving they are eliminated.
   - Guarantee that all 62 tests in the core statutory & physics regression suite pass with 0 failures.
   - Guarantee that the full backend test suite (117 tests) passes with 0 failures.
   - Guarantee that `npm --prefix frontend run build` completes with exit code 0 and 0 TypeScript diagnostics.
   - Achieve a net reduction of **over 1,600 lines of dead code**.

### Scope Boundaries
- **In Scope**:
  - `backend/app/services/federated_edge_engine.py`: Hard deletion.
  - `backend/app/services/markov_deterioration.py`: Hard deletion.
  - `backend/app/api/endpoints/city_brain.py`: Removal of dead routes, schemas, and import cleanup.
  - `backend/app/api/endpoints/analytics.py`: Removal of dead routes and lazy imports.
  - `backend/tests/test_api_endpoints.py`: Update `test_26` to verify HTTP 404 on pruned endpoints.
  - `frontend/src/components/analytics/CityBrainHub.tsx`: Hard deletion.
  - `frontend/src/services/api.ts`: Removal of dead methods and type imports.
  - `frontend/src/types/index.ts`: Removal of dead interfaces.
- **Out of Scope**:
  - Operational endpoints in `city_brain.py` (Knapsack, Shift Triage, XAI Traces, Map Match, 3D Lift, Domain Adaptation) — strictly protected.
  - Operational endpoints in `analytics.py` (Corridors, Trends, Agency Performance, Defect Distribution, POIs, Public Transparency) — strictly protected.
  - Active frontend components (`CommandCenter.tsx`, `WorkOrders.tsx`, `ContractorSlaLedger.tsx`, `WebGISMap.tsx`, `Analytics.tsx`, `RoadMemory.tsx`, `RoadDeteriorationTimeMachine.tsx`) — strictly preserved without regressions.
  - Database schema changes — no migration or table deletion required since no tables were dedicated to these mock engines.

### Threat Model
- **T-14-01: Broken Import Cascades & Silent Runtime NameErrors**:
  - *Risk*: Deleting service files (`federated_edge_engine.py`, `markov_deterioration.py`) could cause unresolved module imports in FastAPI route loaders, crashing the application on startup or on un-mocked endpoint calls.
  - *Mitigation*: Comprehensive static grep sweeps (`git grep "federated_edge_engine"`, `git grep "markov_deterioration"`) across all Python files, followed by immediate FastAPI app instantiation checks and test suite execution.
- **T-14-02: Accidentally Pruning Real Operational Endpoints**:
  - *Risk*: `city_brain.py` and `analytics.py` house critical operational routes (0/1 Knapsack budget optimizer, shift triage, XAI traces, chronic failure clustering, 3D bounding box lifting, corridor risk analytics). Over-zealous deletion might inadvertently prune real municipal features.
  - *Mitigation*: Strict white-listing of operational endpoints. The plan explicitly itemizes the 10 operational `city-brain` endpoints and 7 operational `analytics` endpoints that MUST remain untouched and verified by automated tests.
- **T-14-03: Frontend TypeScript Build & Type Invariant Breakage**:
  - *Risk*: Deleting `CityBrainHub.tsx` or removing types from `types/index.ts` could break downstream components if any active UI view had hidden transitive imports or dependencies on `FleetEdgeDiagnosticsResult`, `FederatedRoundResult`, etc.
  - *Mitigation*: Verified that `CityBrainHub.tsx` was unmounted with zero inbound imports. Pruned types are strictly isolated to `CityBrainHub.tsx` and the two pruned methods in `api.ts`. Enforced verification via `npm --prefix frontend run build` (tsc + vite) ensuring 0 diagnostics.
