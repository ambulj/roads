# Plan 11-01: Work Orders Cockpit & Contractor Operations Overhaul

## Planning Context

### Objective
Transform the municipal Work Orders and Contractor SLA operations in RoadSaathi from standard management lists into an executive, high-contrast, data-dense **Municipal Command Cockpit** in accordance with Milestone `v3.3` and Requirements `WO-01`, `WO-02`, and `WO-03`:
1. **Executive Top Metrics Strip (`WorkOrders.tsx`)**:
   - Deliver a persistent, sleek 4-card executive scorecard strip positioned prominently above the workspace sub-tabs:
     - **Active Work Orders**: Count of ongoing repairs (`open + assigned + in_progress`) with a pure SVG circular completion gauge (% of work orders resolved/closed).
     - **Critical P0 SLA Breaches & Countdowns**: Count of orders within 6h of breach or currently breached, featuring an animated rose SVG circular risk gauge.
     - **Total Escrow At Risk (₹)**: CAG / PFMS contractor retention deposits at stake across active non-closed defects under IRC:SP:20 Clause 14, with financial risk exposure indicator.
     - **3-Pass Verified Repairs**: Count of repairs verified closed by autonomous multi-bus sensor consensus ($G_z < 1.15g$), with a 100% statutory integrity circular ring.
2. **CAD Backlog Table Redesign (`WorkOrders.tsx`)**:
   - Enforce compact cell padding (`py-2.5 px-3`) across all `<th>` and `<td>` elements with subtle borders (`border-slate-200 dark:border-slate-800`).
   - Implement strict monospace tabular numbers (`font-mono tabular-nums text-xs`) for ticket codes (`WO-2026-CHE-XXX`), statutory RPI scores, ₹ volumetric repair costs, and live SLA countdowns.
   - Refine high-contrast severity pills (P0 Critical rose, P1 High amber, P2 Routine slate).
   - Standardize clustered action triggers: `Inspect` (CAD audit drawer + 3D depth mesh modal for road surface defects), `Release Escrow` (multi-pass concurrence gate), and `Dispatch` (instant WhatsApp/SMS ward notice).
   - Maintain multi-column sorting (Ticket ID, RPI, Corridor, Cost, SLA, Status), multi-criteria filter chips, and 1-click RFC 4180 CSV export.
3. **Modern Interactive Kanban Board (`WorkOrders.tsx`)**:
   - Overhaul the Kanban board into 4 high-contrast operational swimlanes: `Assigned`, `In Progress`, `Resolved`, and `Verified Closed`.
   - Modernize Kanban cards to include:
     - Defect image thumbnail with aspect ratio lock and fallback placeholder (`/evidence/bus_pass_1_detect.jpg`).
     - Mini live SVG SLA countdown progress ring (color-coded: green for >12h, amber for 6–12h, rose for <6h or breached).
     - Contractor agency code badge and corridor tag.
     - Statutory concurrence chip (`MultiBusTruthBadge` / `3-Pass Verified`).
     - Card quick action cluster (`Inspect`, `Dispatch`, `Release Escrow`) wiring directly to `WorkOrderActionConsole.tsx`.
     - Smooth 1-click column advancement transitions with toast confirmations.
4. **Contractor Financial SLA Ledger Polish (`ContractorSlaLedger.tsx`)**:
   - Elevate escrow guarantee accounting: display gross bank guarantee bonds (₹Cr), Clause 14 auto-debits (₹Lakhs), and net available balance with visual health indicators.
   - Implement Contractor Debarment Risk Meter badges (`Low` green, `Medium` amber, `Critical Debarment Warning` rose with animated pulsing alert) based on contract breaches and SLA adherence.
   - Enhance Clause 14 Auto-Debit trigger to execute against `/api/contractors/penalties/auto-debit` with realistic telematics payloads ($G_z \ge 1.30g$) and render an authentic, printable Public Financial Management System (PFMS) treasury settlement voucher.
   - Provide a clean dual-view switcher between the Performance SLA Table and Auto-Debit Audit Docket.

### Scope Boundaries
- **In Scope**: `frontend/src/pages/WorkOrders.tsx` and `frontend/src/components/workorders/ContractorSlaLedger.tsx`.
- **Out of Scope**: No backend API routes or database schema changes; preserve all existing contracts and the 34 passing backend regression tests.

### Threat Model
- **T-11-01: Performance & Layout Shift from Animated SVG Gauges and Timer Loops**:
  - *Risk*: Multiple real-time interval timers and un-memoized SVG circular calculations causing DOM re-renders, layout jitter, and high CPU usage.
  - *Mitigation*: Implement lightweight, pure mathematical SVG gauge components using standard `strokeDasharray` / `strokeDashoffset` calculations. Memoize aggregate metric calculations using `useMemo` dependent strictly on `clusters`. Avoid unconstrained JS `setInterval` loops.
- **T-11-02: State Desynchronization between Kanban Transitions, CAD Table, and Action Console**:
  - *Risk*: Advancing a card in the Kanban lane or updating status via `WorkOrderActionConsole` fails to sync the CAD Backlog table or top metrics strip.
  - *Mitigation*: Ensure `clusters` and `onUpdateStatus` remain the unified source of truth. When `requestStatusUpdate` is called, update the parent state immediately, fire toast notifications, and recompute filtered/sorted lists deterministically.
- **T-11-03: Financial & Telematics Inaccuracies in Clause 14 Auto-Debit & PFMS Voucher Generation**:
  - *Risk*: Auto-debit demonstrations failing to observe statutory parameters ($G_z \ge 1.30g$, MoRTH Section 3000) or generating malformed PFMS vouchers without cryptographic SHA-256 evidence stamps.
  - *Mitigation*: Strict enforcement of statutory payload attributes (`measuredGz = 1.48`, `thresholdGz = 1.30`, SHA-256 evidence hash, PFMS transaction reference) in both API calls and UI fallback simulations.
