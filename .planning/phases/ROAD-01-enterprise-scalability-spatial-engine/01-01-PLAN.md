# Plan 01-01: Dual Database Engine & Spatial Geometry Layer

<planning_context>
### Objective
Transition RoadSaathi's persistence layer from a single-city SQLite prototype to an enterprise dual-dialect architecture supporting SQLite WAL for zero-dependency local development and PostgreSQL 16 + PostGIS 3.4 for production multi-fleet scaling (SCALE-01). Introduce a dialect-conditional spatial geometry column (`SpatialPoint`) that renders as PostGIS `geometry(POINT, 4326)` with GiST spatial indexing on PostgreSQL, while compiling to lightweight `Text` on SQLite to avoid native C-library (GDAL/GEOS/libspatialite) install barriers.

### Scope Boundaries
- **In Scope:**
  - URL protocol normalization (`postgresql://` -> `postgresql+asyncpg://`, empty/sqlite -> `sqlite+aiosqlite:///...`).
  - Async engine factory in `backend/app/storage/database.py` with SQLite WAL connection pragmas (`journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=15000`).
  - PgBouncer-safe PostgreSQL connection pooling (`statement_cache_size=0`, `prepared_statement_cache_size=0`, `pool_recycle=300`, `pool_pre_ping=True`, `pool_timeout=10`).
  - Dual `AsyncSessionLocal` and sync `SessionLocal` exports for backward compatibility.
  - Hybrid spatial column type `SpatialPoint` using SQLAlchemy `Text().with_variant(Geometry(geometry_type="POINT", srid=4326, spatial_index=True), "postgresql")`.
  - Schema enhancement for `DBDistressCluster`, `DBRawIngest`, and `DBTrafficIncident` retaining `lat` and `lng` floats alongside the new `geom` column and GiST indexes.
  - Automated test scaffolding in `backend/tests/test_dual_engine.py` and `backend/tests/test_spatial.py`.
- **Out of Scope:**
  - Viewport spatial bounding box REST API filtering (deferred to Plan 01-02).
  - Background telemetry batch flusher queue (deferred to Plan 01-02).
  - Edge NPU zero-copy pipeline or camera capture (Phase 2).

### Threat Model
- **T-01-01: Database Credential Leakage & Connection Hijacking**: Normalizing connection strings or printing connection info must never dump raw database credentials (passwords, auth tokens) in stdout logs or tracebacks.
- **T-01-02: Native C-Library Failure on Local Environments**: Importing GeoAlchemy2 without SpatiaLite native binaries can crash table creation with `RecoverGeometryColumn` missing function errors. Mitigated by using dialect-conditional `with_variant` compiling to pure `Text` on SQLite.
</planning_context>

### Task 2: Hybrid Spatial Geometry Column & GiST Indexing
<name>Dialect-Conditional Spatial Geometry Column & GiST Indexing</name>
<read_first>
- .planning/phases/ROAD-01-enterprise-scalability-spatial-engine/01-CONTEXT.md (Decisions D-05 through D-08)
- .planning/phases/ROAD-01-enterprise-scalability-spatial-engine/01-RESEARCH.md (Section 2: Spatial Geometry Integration)
- backend/app/models/db_models.py (Current database models and schema definitions)
</read_first>
<action>
1. Create `backend/tests/test_spatial.py` with initial schema compilation tests:
   - `test_geometry_compilation_sqlite`: Executes `Base.metadata.create_all()` against an in-memory/temp SQLite engine, asserting zero DDL errors and verifying `geom` column exists as `TEXT`.
   - `test_geometry_compilation_postgres_ddl`: Compiles table schema using `postgresql.dialect()` and verifies `geom` compiles to `geometry(POINT,4326)` and includes GiST indexes.
2. Update `backend/app/models/db_models.py`:
   - Define dialect-conditional type helper `SpatialPoint`:
     ```python
     from sqlalchemy import Text
     from geoalchemy2 import Geometry

     SpatialPoint = Text().with_variant(
         Geometry(geometry_type="POINT", srid=4326, spatial_index=True),
         "postgresql"
     )
     ```
   - Add `geom = Column(SpatialPoint, nullable=True)` to:
     - `DBDistressCluster`
     - `DBRawIngest`
     - `DBTrafficIncident`
   - Retain existing `lat` (Float) and `lng` (Float) columns to maintain zero-copy JSON response contracts and SQLite coordinate compatibility.
   - Add GiST spatial index declarations:
     - `Index('idx_distress_clusters_geom', DBDistressCluster.geom, postgresql_using='gist')`
     - `Index('idx_raw_ingests_geom', DBRawIngest.geom, postgresql_using='gist')`
     - `Index('idx_traffic_incidents_geom', DBTrafficIncident.geom, postgresql_using='gist')`
   - Add spatio-temporal composite indexes:
     - `Index('idx_raw_ingests_time_bus', DBRawIngest.captured_at, DBRawIngest.bus_id)`
3. Ensure existing test suite passes without regressions.
</action>
<acceptance_criteria>

- Compiling table DDL against PostgreSQL dialect generates `geometry(POINT,4326)` and `USING gist` indexes.
- Models retain `lat` and `lng` columns alongside `geom`.
- All tests in `test_spatial.py` pass.
</acceptance_criteria>
